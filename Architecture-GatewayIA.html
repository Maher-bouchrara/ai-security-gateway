Vue d'ensemble — le pipeline

1
Utilisateur Frontend React

L'utilisateur tape un message dans le composant ChatWindow.tsx. Le frontend envoie une requête HTTP (Axios) vers POST /chat (ou /chat/stream pour le mode streaming) avec le texte brut, sans aucun traitement de sécurité côté client — toute la logique se passe côté serveur.

2
Scan Input LLM Guard

Avant même de toucher au texte, la Gateway appelle scan_input(). Les scanners PromptInjection et Jailbreak analysent le message pour détecter une tentative de manipulation du LLM (ex. "ignore tes instructions"). Si is_safe = false, la requête est immédiatement rejetée (HTTP 400) — le LLM n'est jamais appelé.

3
Anonymize Presidio + Vault

Si l'input est jugé sûr, AnalyzerEngine (Presidio, basé sur SpaCy/NER) repère les données personnelles dans le texte (noms, emails, IBAN…). Chacune est remplacée par un token ([PERSONNE_1]…) et la correspondance token → vraie valeur est enregistrée dans la table vault_tokens, avec une expiration de 24h.

4
LLM Cloud via LiteLLM

Le texte tokenisé (jamais le texte original) est envoyé au modèle choisi (GPT-4, Claude, Mistral…) via LiteLLM, une couche d'abstraction qui uniformise l'appel quel que soit le fournisseur. Le LLM ne voit donc jamais aucune donnée personnelle réelle — uniquement des placeholders neutres.

5
Scan Output LLM Guard

La réponse générée par le LLM est à son tour passée dans scan_output(), avec les scanners Toxicity, Sensitive et Relevance. Si la réponse est jugée toxique ou hors-sujet, elle est remplacée par un message générique avant d'aller plus loin.

6
Deanonymize Vault lookup

deanonymize() relit la table vault_tokens et remplace chaque token encore présent dans la réponse par sa vraie valeur d'origine (ex. [PERSONNE_1] redevient "Marie Martin"). C'est le "matching inverse" demandé dans le sujet — uniquement possible parce que la Gateway a gardé la correspondance localement.

7
Utilisateur Réponse finale

Le frontend reçoit la réponse complète (ou le flux SSE token par token), l'affiche dans ChatMessage.tsx avec un badge de risque coloré, et chaque étape du pipeline a été enregistrée comme événement dans audit_events — visible ensuite dans le Dashboard.

RéponseChatResponse(reply, tokens_used, pii_detected)

RôleMême pipeline que /chat, mais réponse envoyée en flux continu (SSE) au lieu d'un seul bloc
