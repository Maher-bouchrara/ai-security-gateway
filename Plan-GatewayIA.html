📋 Le sujet, en clair

Sujet officiel (Réf. 01-2026) : "Développement de Gateway de Sécurité IA & Anonymisation Réversible." Techs imposées : LLM, Python, React.js, TypeScript, API REST.

En une phrase : les employés veulent utiliser des LLM puissants (ChatGPT, Claude…) pour leur travail, mais ils tapent parfois des données sensibles (noms, IBAN, emails de clients…) dans leurs messages. Le RGPD interdit d'envoyer ces données à un tiers (le fournisseur du LLM) sans contrôle. Ton projet construit une passerelle (gateway) qui s'intercale entre l'utilisateur et le LLM : elle retire automatiquement les données sensibles avant l'envoi, les remplace par des jetons (tokens), puis les remet à la bonne place dans la réponse — sans que le LLM n'ait jamais vu la vraie donnée.

Les 4 fonctionnalités demandées dans le sujet, et où elles correspondent dans ton plan :

  • Anonymisation dynamique par Vaulting — détecter les PII et les remplacer par des tokens avant l'envoi au LLM → Sessions 4-5
  • Sécurisation des flux (Input/Output) — bloquer les tentatives de manipulation du LLM en entrée, vérifier la toxicité en sortie → Session 6
  • Matching inverse et Désanonymisation — remettre les vraies données dans la réponse finale grâce au Vault → Session 5 (et assemblé en Session 7)
  • Dashboard d'Audit — interface qui montre les tentatives d'attaque et la latence ajoutée par la sécurité → Sessions 8, 12-14

📖 Glossaire — tous les mots techniques du projet

Pas besoin de tout retenir d'un coup : reviens ici à chaque fois qu'un terme te bloque dans une session.

Concepts métier / sécurité
RGPDRèglement européen sur la protection des données personnelles. Encadre strictement ce qu'on a le droit de faire avec des données comme un nom ou un email.
PIIPersonally Identifiable Information — toute donnée qui permet d'identifier une personne (nom, email, IBAN, téléphone…).
LLMLarge Language Model — le modèle d'IA générative (ex. GPT, Claude) auquel on envoie les messages.
LLM GuardLibrairie Python qui scanne les messages envoyés/reçus d'un LLM pour détecter attaques et contenus à risque.
Vaulting / VaultLe "coffre-fort" : une base de données qui stocke le lien entre un token et la vraie valeur qu'il remplace, pour pouvoir la retrouver plus tard.
TokenisationRemplacer une donnée sensible par un identifiant neutre (ex. [PERSONNE_1]) qui ne révèle rien en lui-même.
Anonymisation / DésanonymisationAnonymisation = remplacer la donnée par un token avant l'envoi au LLM. Désanonymisation = l'opération inverse sur la réponse, pour l'utilisateur final.
Matching inverseLe mécanisme qui retrouve, à partir d'un token vu dans la réponse du LLM, la vraie valeur d'origine stockée dans le Vault.
Prompt Injection / JailbreakingTechnique où un utilisateur essaie de manipuler le LLM pour lui faire ignorer ses instructions de sécurité (ex. "Ignore tes instructions précédentes...").
ToxicitéContenu offensant, haineux ou dangereux qu'un LLM pourrait générer en sortie, et qu'il faut filtrer avant de l'afficher.
Audit / Dashboard d'AuditLe suivi de tout ce qui se passe (tentatives d'attaque, PII détectées, latence) affiché sous forme de graphiques pour un humain.
LatenceLe temps ajouté par une étape (ici, la couche de sécurité) avant que l'utilisateur reçoive sa réponse.
NERNamed Entity Recognition — technique de NLP qui repère dans un texte les entités nommées (personne, lieu, date…), utilisée par Presidio pour détecter les PII.
NLPNatural Language Processing — traitement automatique du langage humain par un programme.
Backend
FastAPIFramework Python pour construire des APIs REST rapidement, avec validation automatique et documentation Swagger générée toute seule.
PydanticLibrairie qui valide la forme des données entrantes/sortantes d'une API à partir de classes Python typées.
async / awaitMécanisme Python pour exécuter du code sans bloquer le programme pendant qu'on attend une réponse (ex. un appel réseau au LLM).
ORMObject-Relational Mapping — permet de manipuler une base de données avec des objets/classes Python plutôt qu'en écrivant du SQL à la main.
SQLAlchemyL'ORM Python le plus utilisé, ici en version async pour fonctionner avec FastAPI.
CRUDCreate / Read / Update / Delete — les 4 opérations de base sur des données en base.
JWTJSON Web Token — un jeton signé qui prouve qu'un utilisateur est authentifié, envoyé dans chaque requête protégée.
SSEServer-Sent Events — technologie qui permet au serveur d'envoyer des petits bouts de réponse au fur et à mesure (utilisé pour le streaming du chat).
CORSCross-Origin Resource Sharing — règle de sécurité du navigateur qu'il faut explicitement autoriser pour que le frontend (autre origine) puisse appeler le backend.
LiteLLMLibrairie qui uniformise l'appel à différents LLM (OpenAI, Anthropic, Mistral…) avec la même syntaxe.
Microsoft PresidioOutil open-source de Microsoft pour détecter et anonymiser des PII dans du texte.

ViteOutil de build/démarrage ultra-rapide pour les projets frontend modernes (remplace l'ancien Create React App).

RechartsLibrairie de graphiques (charts) pour React, utilisée pour le Dashboard d'Audit.
ReadableStreamAPI web standard pour lire un flux de données (ici, les événements SSE) morceau par morceau.
Tests & Outils
pytestFramework de tests automatisés pour Python.
MockRemplacer temporairement une vraie dépendance (ex. l'appel au LLM) par une fausse version contrôlée, pour tester sans dépendre d'un service externe.
PlaywrightOutil de tests end-to-end (E2E) qui pilote un vrai navigateur pour simuler un utilisateur.

Vault — Tokenisation reversible
Remplacer les vraies donnees par des tokens, puis pouvoir les retrouver plus tard
▼
↩ Recap session précédente : Tu sors de S4 avec PIIDetector qui détecte 15 types de données personnelles en français.

C'est le coeur technique de l'anonymisation reversible : la donnee sensible ne part jamais vers le LLM, mais ton systeme garde une trace pour la reinjecter dans la reponse finale.

Mots-clés à connaître

Étapes
  • 1.Ajoute a anonymizer.py la methode anonymize(text, session_id) -> AnonymizeResult, qui renvoie le texte tokenise + un mapping (dict token -> valeur reelle). Ex : "Bonjour Marie Martin" devient "Bonjour [PERSONNE_1]".
  • 2.Sauvegarde chaque entree dans vault_tokens, avec une expiration de 24h (TTL) — un token ne doit pas rester valable indefiniment.
  • 3.Ajoute deanonymize(text, session_id) -> str qui relit le Vault et remplace chaque token par sa vraie valeur — l'operation inverse, appliquee sur la reponse du LLM.
  • 4.Test bout en bout manuel : anonymise un texte -> envoie au LLM -> desanonymise la reponse -> verifie que les vraies valeurs reapparaissent.
